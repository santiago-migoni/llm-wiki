# Inventario de ciclo de vida para adaptación a Codex

**Alcance.** Lectura del repositorio de referencia `.repos/obsidian-second-brain` desde su fuente real. Este documento inventaría capacidades y límites para una evaluación de adaptación; no aprueba diseño ni implementación, y no modifica el repositorio fuente. La revisión de este anexo es estática; las comprobaciones ejecutadas por el coordinador se identifican en VERIFICACION.json.

## Cobertura y límites

| Área | Cobertura inspeccionada | Recuento/omisión |
|---|---|---|

## Qué conservan o dejan fuera los builds relevantes

- `adapters/agent-skills/adapter.sh` crea `skills/<comando>/SKILL.md`, añade preámbulo de root/vault, incorpora `ai-first-rules.md` dentro de cada skill y crea `skills/obsidian-core/` con `references/`, `scripts/` y `pyproject.toml`. Es el build recomendado para Codex CLI en el repo fuente. La función `_ask_emit_core` copia únicamente `references/`, `scripts/` y `pyproject.toml`; no copia `hooks/` ni `integrations/`. La ausencia de su empaquetado se infiere de esas rutas de copia, mientras que `INSTALL.md` llama a los agentes programados extras Claude/Hermes. No hay hook Codex automático configurado por el adapter.
- `adapters/codex-cli/adapter.sh` también emite skills nativas `.agents/skills/<comando>/SKILL.md`, `AGENTS.md`, `.codex/references`, `.codex/scripts` y `pyproject.toml`; su `INSTALL.md` marca el build como deprecated en favor de `agent-skills`. Dice que no distribuye `hooks/validate-ai-first.sh` y que el usuario debe abrir Codex desde root del vault o git root.
- `scripts/build.sh` borra/recrea solo `dist/<platform>` antes de llamar adapter; valida nombres `exclude:`. Puede copiar scripts de research junto con el engine, pero eso no significa que la capacidad completa esté validada aquí. Se limpiará bytecode del dist.
- `scripts/install-codex-wrappers.sh` instala comandos que terminan en `codex exec`; `scripts/run-command.sh` arma un prompt desde Markdown. La documentación del adapter Codex actual dice explícitamente que native skills corren en la sesión, sin wrapper. Es un camino legado, separado del Agent Skills recomendado; falta verificar referencias externas/README completos para decidir retiro.
